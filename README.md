# МГТУ — день открытых дверей

Сайт с каталогом 59 программ и защищённым редактором. Сервер — Node.js 24+ без внешних npm-зависимостей, данные — SQLite. Дизайн и анимации находятся в `dist/`.

## Логотип

Во всех местах используется официальный горизонтальный белый логотип из брендбука (исходный файл `logovert_white.png`): `dist/assets/logo-white.png`. Исходный PNG сохранён без изменения пикселей и прозрачности. На светлых экранах редактора логотип размещён на синей плашке. `logos.css` задаёт размеры для компьютеров и телефонов; `assets/favicon.svg` содержит тот же логотип на синем фоне. Совместимый путь `assets/crest.png` содержит этот же файл для прежних сохранённых настроек.

## Роли и доступ

- **Администратор:** тексты, оформление, шрифты, размеры, цвета, фотографии, ссылки, видимость разделов, условия приёма; создание, изменение, блокировка и удаление пользователей, назначение ролей и сброс паролей.
- **Редактор:** только текст: заголовки, описания, подписи, контакты, числа в текстовых карточках, текстовые условия приёма и существующие ячейки таблиц. Нельзя менять оформление, адреса ссылок, файлы фотографий, уровень программы, видимость, структуру таблиц или пользователей.
- **Посетитель:** просмотр опубликованного сайта. Вход в редактор закрыт до авторизации.

Права проверяются сервером на каждом запросе. Роль не берётся из localStorage или тела запроса. При сохранении редактором сервер сравнивает изменения с опубликованной версией и допускает только текстовые поля.

Пароли хешируются scrypt с индивидуальной солью. Сессии хранятся в SQLite в виде хешей случайных токенов; браузер получает HttpOnly/SameSite cookie. Срок сессии — 8 часов. Есть защита от CSRF, ограничение попыток входа, отзыв сессий при блокировке, смене роли, логина или пароля. Удалить или заблокировать себя через интерфейс нельзя. Последний действующий администратор сохраняется. API не возвращает хеши паролей.

## Запуск на сервере

См. [DEPLOY.md](DEPLOY.md): обновление `/home/abitdod/app_2504`, порт **6065**, создание первого администратора и перенос прежних браузерных правок.

```sh
cp .env.example .env
# Проверьте APP_ORIGIN: точный адрес, по которому открывается сайт.
docker compose up -d --build
docker compose exec web node server/create-admin.mjs admin
```

Последняя команда запрашивает пароль в терминале без отображения. Дефолтных паролей и публичной регистрации нет. Вводите собственный пароль не короче 12 символов. Повторный запуск команды для существующего логина сбрасывает пароль, возвращает роль администратора и отзывает сессии — это восстановление с доступом к серверу.

SQLite хранится в Docker volume `site-data`. Пересборка контейнера сохраняет пользователей и опубликованный контент. Не удаляйте этот volume (`docker compose down -v` удаляет данные).

Статический Nginx без Node API для этой версии не подходит. Файл `docker/nginx.conf` сохранён как прежняя конфигурация, новый Dockerfile его не использует. Прежняя публикация Sites не обновляется этим развёртыванием на собственном сервере.

## Локальный запуск

```sh
npm run dev
# В другом интерактивном терминале:
npm run admin:create -- admin
```

Сайт: http://127.0.0.1:4173/ · Редактор: http://127.0.0.1:4173/admin.html.

Локальные данные лежат в `runtime-data/site.sqlite`. Переменные: `DATA_DIR` — каталог SQLite, `HOST`/`PORT` — адрес прослушивания. В production обязательно задаётся `APP_ORIGIN`, например `https://example.org`; для HTTPS также `COOKIE_SECURE=true`. APP_ORIGIN не содержит завершающего слеша или пути. Если используется reverse proxy, адрес соответствует внешнему адресу браузера. Заголовки X-Forwarded-* не используются для определения полномочий или доверенного origin.

## Публикация контента

«Сохранить на сайте» записывает правки в SQLite; при открытии страницы все посетители получают одну опубликованную версию через `/api/content`. Предпросмотр до сохранения виден только текущему редактору. Одновременное сохранение устаревшей версии возвращает конфликт 409, не перезаписывая чужую работу.

Старые данные localStorage не применяются автоматически. Администратор может открыть их через **Мой аккаунт → Открыть локальный черновик**, проверить предпросмотр и сохранить на сайте. Исходная браузерная копия остаётся. Для переноса нужно зайти с того же адреса и браузера, где сохранены прежние правки.

Приглашённый пользователь получает логин и начальный пароль от администратора отдельно. На странице **Мой аккаунт** он может сменить собственный пароль; после этого требуется повторный вход на всех устройствах.

Регистрация на день открытых дверей пока остаётся демонстрационной: заявки не сохраняются и не отправляются. Эта задача добавляет пользователей редактора и публикацию контента, а не обработку заявок.

## Проверки

```sh
npm run check
npm test
```

API-тесты проверяют запрет доступа без входа, серверные роли, подмену полномочий, текстовое редактирование, запрет оформления/ссылок/фотографий/структуры, CSRF, опасные данные, коллизии версий, блокировку, отзыв и истечение сессий, смену и сброс паролей, ограничение входов и сохранение данных при перезапуске. Тестовая SQLite создаётся во временном каталоге и удаляется после теста.
