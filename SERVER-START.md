# Выгрузка сайта на openday.mkgtu.ru

Готовая конфигурация: **https://openday.mkgtu.ru**. Сервер: **172.17.254.145**. Папка проекта: **/home/abitdod/app_2504**. Приложение внутри сервера продолжает использовать порт **6065**; существующий HTTPS-прокси домена не меняется.

## 1. Загрузить архив

Заново скачайте mgtu-openday-server.zip. Через SFTP загрузите его в /home/abitdod/app_2504 с заменой прежнего архива. Не удаляйте папку проекта, .env или Docker volumes.

## 2. В SSH-терминале сохранить старые файлы и распаковать архив

Все команды выполняются на сервере, не в PowerShell компьютера. Вставьте блок целиком:

```sh
cd /home/abitdod/app_2504 &&
mkdir -p backups &&
chmod 700 backups &&
tar --exclude='./backups' --exclude='./mgtu-openday-server.zip' --exclude='./mgtu-server-upload.zip' --exclude='./node_modules' --exclude='./runtime-data' --exclude='./.git' -czf "./backups/files-$(date +%Y%m%d-%H%M%S).tar.gz" . &&
unzip -o mgtu-openday-server.zip &&
sh deploy-server.sh
```

Если команда завершится ошибкой, следующий шаг не выполнится. Пришлите текст ошибки, скрыв персональные данные и пароли. Если нет unzip, попросите администратора установить его либо распакуйте архив на компьютере и загрузите его содержимое вместе со скрытыми файлами .dockerignore и .env.example.

## 3. Что скрипт сделает сам

- Проверит Docker, Compose и комплектность файлов.
- Создаст backups внутри проекта, где не требуются права на родительскую папку.
- Сохранит прежний .env в backups, если он существует.
- Установит APP_ORIGIN=https://openday.mkgtu.ru и COOKIE_SECURE=true. SMTP, порт, HOST_IP, COMPOSE_PROJECT_NAME и остальные настройки сохранятся.
- Для новой установки использует .env.example с портом 6065.
- Сделает резервную копию SQLite работающего Node-контейнера. При ошибке этой копии остановится до пересборки.
- Пересоберёт и запустит сайт, дождётся ответа healthz и напечатает ok.

Старый Nginx-контейнер статического сайта не имеет серверной SQLite: для него используется копия файлов из шага 2. Неизвестный тип работающего контейнера скрипт не обновляет автоматически.

При permission denied на Docker не меняйте права на его сокет — передайте ошибку администратору сервера. Если порт 6065 занят, не останавливайте неизвестные приложения наугад.

## 4. Открыть сайт и админку

- Сайт: https://openday.mkgtu.ru/
- Админка: https://openday.mkgtu.ru/admin.html

Используйте именно HTTPS. Домен уже отвечает по HTTPS; существующий reverse proxy должен продолжать направлять запросы к приложению на порту 6065.

Существующие серверные пользователи сохраняются. Локальный пароль с компьютера на сервер автоматически не переносится. Для первой установки или намеренного восстановления доступа выполните:

```sh
cd /home/abitdod/app_2504
docker compose exec web node server/create-admin.mjs admin
```

Задайте пароль минимум из 12 символов дважды. Ввод скрыт. Логин admin. Для существующего admin эта команда заменит пароль и завершит прежние сессии — при обычном обновлении запускать её не нужно.

## 5. Обновление баллов с abit.mkgtu.ru

В админке откройте «Направления» → «Обновить из источника». Проверьте дату и результат. Текущее сопоставление — 58 программ; «Химия» отсутствует в источнике. Автообновление — при запуске и каждые 6 часов.

Проверенный Linux-контейнер получил SELF_SIGNED_CERT_IN_CHAIN. Для автоматического обновления нужен доверенный PEM-сертификат удостоверяющего центра сервера abit.mkgtu.ru, полученный у администратора. Положите его в docker/abit-ca.pem, добавьте настройки из compose.ca.example.yaml в compose.override.yaml и повторите sh deploy-server.sh. Существующий override-файл объедините с примером, сохранив остальные настройки.

На компьютере доверие обеспечивается локальным Kaspersky; его сертификат в архив не включён. Не отключайте проверку HTTPS. До первого успешного импорта прежние встроенные условия не считаются подтверждёнными. После успешного импорта при недоступности источника остаётся последняя копия.

## 6. Заявки и почта

Заявки сохраняются в админке. Почтовое дублирование ожидает настоящих SMTP-настроек. В серверном .env заполните SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASSWORD, MAIL_FROM и MAIL_TO и снова запустите sh deploy-server.sh. Он сохранит эти параметры. Без SMTP письма остаются в очереди. Пароль в .env заключайте в одинарные кавычки. Подробнее — DEPLOY.md.

## 7. Проверка и диагностика

```sh
cd /home/abitdod/app_2504
docker compose ps
docker compose logs --tail=100 web
curl -fsS http://127.0.0.1:6065/healthz
```

Не присылайте полный .env, пароли или содержимое заявок. Не выполняйте docker compose down -v: в томах хранятся пользователи, опубликованные правки, заявки и кэш. Запускайте обновления из той же папки и с тем же именем Compose-проекта. Резервные копии хранятся в /home/abitdod/app_2504/backups.
