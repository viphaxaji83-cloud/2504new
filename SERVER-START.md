# Загрузка сайта на сервер

Адрес: **http://172.17.254.145:6065/**. Папка: **/home/abitdod/app_2504**.

## 1. Что загрузить через SFTP

Слева на компьютере выберите `mgtu-server-upload.zip`, справа откройте `/home/abitdod/app_2504` и перетащите туда архив. Перед обновлением не удаляйте папку проекта и файлы `.env`, `compose.override.yaml`.

Архив содержит сайт, сервер, Dockerfile, Compose, package-lock.json, настройки-пример, скрипт запуска и инструкции. Файлы лежат в корне архива — дополнительной папки внутри нет. Локальных учётных записей, паролей, базы, заявок и настоящих SMTP-настроек в архиве нет.

## 2. Открыть SSH-терминал

В той же программе, где открыт SFTP, переключитесь на терминал подключения к `172.17.254.145`. Все команды ниже выполняются **на сервере**, а не в PowerShell Windows.

Проверьте Docker и Compose:

```sh
cd /home/abitdod/app_2504
docker version
docker compose version
```

Если Docker не установлен, демон недоступен или написано `permission denied` — передайте вывод администратору сервера. Скрипт не меняет права доступа к Docker.

## 3. Сохранить старые файлы и распаковать новую версию

Выполните одним блоком:

```sh
cd /home/abitdod/app_2504
mkdir -p ./backups
chmod 700 ./backups
tar --exclude='./backups' --exclude='./mgtu-server-upload.zip' --exclude='./node_modules' --exclude='./runtime-data' --exclude='./.git' -czf "./backups/files-$(date +%Y%m%d-%H%M%S).tar.gz" .
unzip -o mgtu-server-upload.zip
```

Старые файлы сохранятся в папке `backups` внутри проекта. Существующий `.env` останется: его нет в архиве. Если `unzip` отсутствует, попросите администратора установить его или распакуйте архив на компьютере и загрузите его **содержимое** в папку проекта, включая `.dockerignore` и `.env.example`.

## 4. Настроить адрес сайта

Если `.env` ещё нет, создайте его из примера, не заменяя существующий:

```sh
test -f .env || cp .env.example .env
chmod 600 .env
nano .env
```

В файле должны быть эти значения:

```dotenv
APP_ORIGIN=http://172.17.254.145:6065
HTTP_PORT=6065
HOST_IP=0.0.0.0
COOKIE_SECURE=false
```

В `nano`: сохранить — Ctrl+O, Enter; выйти — Ctrl+X. Остальные существующие параметры, в том числе `COMPOSE_PROJECT_NAME`, сохраните. Если вместо IP используется домен — задайте точный адрес в APP_ORIGIN без завершающего слеша. При HTTPS установите COOKIE_SECURE=true.

## 5. Запустить сайт

```sh
cd /home/abitdod/app_2504
sh deploy-server.sh
```

Скрипт проверит конфигурацию, сделает копию SQLite работающего Node-контейнера, пересоберёт сайт и проверит его ответ. При ошибке резервного копирования Node-базы он остановится до обновления. Старый статический Nginx-контейнер не имеет этой базы — для него сохраняется копия файлов из шага 3.

В конце должно появиться `ok`. Дополнительно проверьте внешний порт:

```sh
curl -fsS http://127.0.0.1:6065/healthz
docker compose ps
```

Затем откройте **http://172.17.254.145:6065/**. Если на сервере ответ есть, а с компьютера сайт не открывается, попросите администратора проверить доступ к TCP-порту 6065 из вашей сети. Если порт уже занят другим приложением, не останавливайте его наугад — покажите администратору `docker ps`.

## 6. Вход в админку

Адрес: **http://172.17.254.145:6065/admin.html**.

Если сайт уже использовал серверную админку, сохранённые пользователи продолжают работать. **Локальный пароль с компьютера автоматически на сервер не переносится.**

Только при первой установке либо для намеренного восстановления пароля:

```sh
docker compose exec web node server/create-admin.mjs admin
```

Введите свой пароль дважды, минимум 12 символов. Ввод не отображается — это нормально. Логин будет `admin`. Если такой пользователь уже есть, команда **заменит его пароль**, вернёт права администратора и завершит его прежние сессии.

## 7. Загрузка баллов с abit.mkgtu.ru

В админке откройте «Направления» → «Обновить из источника». Проверьте дату и результат. Нормальный результат текущего сопоставления — 58 направлений; «Химия» отсутствует в источнике. Автоматическое обновление выполняется при запуске и каждые 6 часов.

При проверке этой сборки Linux-контейнер вернул SELF_SIGNED_CERT_IN_CHAIN. Для работы автоматического обновления администратор должен предоставить доверенный PEM-сертификат удостоверяющего центра **сервера abit.mkgtu.ru**. Положите его в `docker/abit-ca.pem`, скопируйте настройки из `compose.ca.example.yaml` в `compose.override.yaml` и повторите `sh deploy-server.sh`. Существующий override-файл объединяйте с примером, не стирая его настройки.

На нашем компьютере HTTPS проверяется через сертификат локального Kaspersky. Этот сертификат не включён в архив: он относится к проверке трафика на компьютере и не доказывает, какой сертификат нужен Linux-серверу. Не используйте NODE_TLS_REJECT_UNAUTHORIZED=0 или отключение проверки HTTPS.

Если первый импорт не удался, дата обновления будет отсутствовать; не считайте прежние встроенные условия приёма подтверждёнными. При ошибках после успешного импорта остаётся последняя сохранённая копия.

## 8. Отправка заявок на почту

Заявки уже сохраняются в админке. Для писем заполните в серверном `.env` реальные параметры:

```dotenv
SMTP_HOST=smtp.example.ru
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=sender@example.ru
SMTP_PASSWORD='пароль SMTP'
MAIL_FROM=sender@example.ru
MAIL_TO=recipient@example.ru
```

Адреса выше — только пример. Для порта 465 задайте SMTP_SECURE=true. Пароль заключайте в одинарные кавычки, особенно если он содержит `$` или `#`. После изменений выполните `sh deploy-server.sh`. Без SMTP заявки сохраняются, а письма ожидают в очереди. После подключения SMTP отправьте одну тестовую заявку и проверьте её появление в админке и в почтовом ящике.

## 9. Если что-то не работает

```sh
cd /home/abitdod/app_2504
docker compose logs --tail=100 web
docker compose ps
```

Скопируйте текст ошибки и пришлите его сюда, скрыв пароли, содержимое заявок и персональные данные. Не присылайте полный `.env`.

**Не выполняйте `docker compose down -v` и не удаляйте Docker volumes:** в них находятся пользователи, заявки, опубликованные правки и кэш приёма. Запускайте обновления из той же папки и с тем же именем Compose-проекта.
