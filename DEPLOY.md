# Обновление сайта на сервере 172.17.254.145:6065

Эта версия добавляет серверный вход, роли и общее сохранение контента. Старый Nginx-контейнер необходимо пересобрать; копирования только dist недостаточно.

1. Загрузите новые `Dockerfile`, `compose.yaml`, `.dockerignore`, `package.json`, `package-lock.json`, `deploy-server.sh`, папки `server/` и `dist/` в `/home/abitdod/app_2504`. Архив mgtu-server-upload.zip содержит эти файлы. Сохраните существующий `.env`, добавив APP_ORIGIN, как показано ниже. Перед обновлением сохраните копию прежних файлов.
2. В SSH-терминале проверьте `.env`:

```sh
cd /home/abitdod/app_2504
```

Для текущего адреса содержимое должно включать:

```dotenv
HOST_IP=0.0.0.0
HTTP_PORT=6065
APP_ORIGIN=https://openday.mkgtu.ru
COOKIE_SECURE=true
```

APP_ORIGIN — точный внешний адрес без завершающего слеша. Если открываете сайт по домену, укажите домен. Для HTTPS используйте `APP_ORIGIN=https://ваш-домен` и `COOKIE_SECURE=true`. При доступе по сети пароли следует передавать через HTTPS; текущий HTTP-адрес предназначен для внутренней сети. TLS настраивается на серверном reverse proxy, не в браузерной админке.

3. Пересоберите и запустите:

```sh
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:6065/healthz
```

Healthcheck должен вернуть `ok`. Если нет:

```sh
docker compose logs --tail=100 web
```

4. Создайте первого администратора:

```sh
docker compose exec web node server/create-admin.mjs admin
```

Пароль задаётся дважды в терминале, ввод скрыт. Не менее 12 символов. Команда выполняется внутри запущенного контейнера от того же пользователя, которому принадлежит база. Учётных записей с заранее заданными паролями нет.

5. Откройте https://openday.mkgtu.ru/admin.html. Войдите под `admin`, затем в разделе **Пользователи** создайте остальные учётные записи. Обычным пользователям назначьте **Редактор — только текст**. Для каждого можно изменить имя, логин и роль, выдать новый пароль, запретить доступ или удалить учётную запись. Изменения доступа отзывают прежние сессии.
6. Если раньше сохраняли макет в браузере, войдите как администратор в том же браузере на том же адресе, откройте **Мой аккаунт → Открыть локальный черновик**. Проверьте предпросмотр, затем нажмите **Сохранить на сайте**. До этого шага локальные правки не публикуются для остальных посетителей.

## Данные и восстановление

Пользователи, сессии и опубликованный сайт находятся в `site.sqlite` в именованном Docker volume `site-data` (фактическое имя включает имя Compose-проекта). Обновления через `docker compose up -d --build` сохраняют volume. Не применяйте `docker compose down -v` к работающему сайту: это удаляет данные.

Забытый пароль администратора восстанавливается той же командой `create-admin.mjs admin` из SSH-терминала. Она также снимает блокировку, возвращает роль администратора и завершает старые сессии. Публичной страницы сброса пароля нет.

Для резервной копии:

```sh
docker compose exec web node server/backup.mjs
# Команда напечатает путь в /tmp. Подставьте его вместо /tmp/ИМЯ.sqlite:
docker compose cp web:/tmp/ИМЯ.sqlite ./site-backup.sqlite
```

Копия содержит данные доступа и контент: храните её отдельно от публичной папки dist и с ограниченным доступом. Для восстановления остановите web и восстановите SQLite в том же volume; не копируйте базу поверх работающей.

## Проверка после установки

- Без входа /admin.html открывает страницу авторизации.
- Администратор видит Оформление и Пользователи.
- Редактор не видит оформление, источники фотографий, URL, видимость и управление пользователями; ему доступны текстовые поля.
- Сохранённый текст появляется в другом браузере после обновления страницы.
- После блокировки пользователь должен войти заново, а вход остаётся запрещённым до разблокировки.


## Заявки и копии на почту

В `.env` задайте параметры своего отправителя и получателя:

```dotenv
SMTP_HOST=smtp.example.ru
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=sender@example.ru
SMTP_PASSWORD="пароль приложения или SMTP"
MAIL_FROM=sender@example.ru
MAIL_TO=recipient@example.ru
```

Для порта 465 используйте `SMTP_SECURE=true`. На 587 требуется STARTTLS.
Если внутренний SMTP-релей не использует авторизацию, оставьте SMTP_USER и SMTP_PASSWORD пустыми; TLS всё равно обязателен.
Несколько адресов получателей перечисляются через запятую в MAIL_TO. Файл .env и SQLite не загружайте в Git.

После изменения параметров: `docker compose up -d --build`. Для локального запуска: `npm ci`, затем `npm start` (читает .env). Существующие заявки и учётные записи остаются в том же томе site-data.

Каждая заявка сначала сохраняется в SQLite, затем копия отправляется фоновым обработчиком. Без SMTP копия остаётся в очереди; после настройки и перезапуска очередь возобновляется. При ошибке — до пяти попыток с увеличением интервала (1, 2, 4, 8 минут). После пяти неудач администратор может нажать «Повторить отправку письма». Индикатор «Отправлено» означает принятие SMTP-сервером, а не прочтение адресатом. При обрыве соединения после принятия письма SMTP-сервером возможна повторная копия; номер заявки и Message-ID сохраняются.

Раздел «Заявки» доступен только администратору. Есть поиск, фильтр, постраничный список по 50 записей и статусы «Новая», «Связались», «Обработана». Счётчик новых обновляется каждые 30 секунд; список и состояние писем — кнопкой «Обновить». Изменение статуса заявки не меняет состояние доставки письма.

Форма требует согласие, проверяет поля на сервере, ограничивает частоту отправок (5 новых заявок за 15 минут с одного адреса) и предотвращает дубли при повторе одного запроса. При недоступном SMTP посетитель всё равно получает подтверждение сохранённой заявки. Резервная копия SQLite содержит заявки и очередь писем.


## Автоматические условия приёма

Источник: https://abit.mkgtu.ru/programs. Сервер читает сериализованные JSON-данные внутри HTML каталога; JavaScript источника не исполняется. Сопоставление по коду и уровню, отдельно от филиала. Поля: год, профиль, статус набора, суммарные бюджетные и платные места, обязательные предметы и предметы на выбор с минимумами ЕГЭ, срок обучения, примечания и ссылки. СПО, вступительные магистратуры и разбивка квот/мест по формам в этой структуре отсутствуют: прежние ручные значения не подмешиваются. Подробности доступны по ссылке в источник. Краткие описания и оформление остаются локальными.

Обновление при запуске и раз в 6 часов; администратор может запустить вручную. Условия приёма и ссылки защищены сервером от ручной подмены, даже администратором. SQLite хранит последнюю успешную копию и время загрузки. При ошибке структуры, невалидных данных или сопоставлении менее 90% местного каталога обновление отклоняется целиком. Изменение данных увеличивает ревизию контента, чтобы открытый черновик не перезаписал новые условия.

Первое сопоставление: 58 из 59 направлений; «Химия» 04.03.01 отсутствует в источнике. Для отсутствующей программы выводится сообщение, прежние баллы и места не считаются актуальными. Новые программы автоматически не добавляются: нужны карточки и сопоставление.

Запуск использует --use-system-ca (Node.js 24.6+), сохраняя проверку HTTPS. На Windows это использует доверенные системные сертификаты. Для контейнера с внутренним удостоверяющим центром разместите предоставленный ИТ-службой PEM-сертификат, например docker/abit-ca.pem, и создайте compose.override.yaml:

```yaml
services:
  web:
    environment:
      NODE_EXTRA_CA_CERTS: /run/certs/abit-ca.pem
    volumes:
      - ./docker/abit-ca.pem:/run/certs/abit-ca.pem:ro
```

Затем docker compose up -d --build. Добавляйте только проверенный сертификат вашего удостоверяющего центра. Проверка HTTPS не отключается; без доверия к источнику обновление отобразит ошибку, сохранив имеющуюся копию. Резервная копия SQLite включает кэш приёма.
